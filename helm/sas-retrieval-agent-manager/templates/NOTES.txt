Removing the SASLogon change
----------------------------
Both changes this release makes inside Viya -- the issuer URI and the OAuth client --
are stored by Viya's own services, so 'helm uninstall' leaves them in place. Undo them
with the same APIs, authenticated as a Viya administrator:
{{- if .Values.integrations.viya.sso.configureSASLogon }}

  1. Read what the issuer was before this release changed it:

       kubectl get configmap -n {{ .Release.Namespace }} {{ printf "%s-saslogon-backup" (include "viya.sso.fullname" .) }} \
         -o jsonpath="{.data.existed} {.data.issuer-uri}"; echo

     'false' means there was no sas.logon.jwt configuration at all, so reverting means
     DELETE-ing the one this release created. Otherwise restore the recorded value.

     The configuration.json key of the same ConfigMap holds the rest of the original
     object for reference, with any signing key or secret removed -- a ConfigMap is not
     the place for those. Its 'redacted' array names what was dropped. Nothing needs
     them to revert: only issuer.uri changed, and the siblings were never overwritten.

  2. Apply the revert against {{ include "viya.sso.url" . }}/configuration/configurations,
     then restart sas-logon-app -- the issuer does not change until it does:

       kubectl -n {{ .Values.integrations.viya.namespace | default "<viya-namespace>" }} rollout restart deploy/sas-logon-app
{{- end }}
{{- if .Values.integrations.viya.sso.registerClient }}

  3. Remove the OAuth client this release registered:

       DELETE {{ include "viya.sso.url" . }}/SASLogon/oauth/clients/{{ .Values.integrations.viya.sso.clientId }}
{{- end }}
{{- end }}
